# RECT-DESTROYER

Odin + raylib brickbreaker. One package, `package src`, built from the repo root:

```
odin check src
odin run src
```

Level and config paths are relative to that working directory (`src/levels/`, `src/rect_types.txt`, `src/powerup_types.txt`, `src/super_powerup_types.txt`). Finished runs are written to `scores.txt` there. The window opens at 800×600, titled `RECT-DESTROYER! 26_1.0.1`, and can be resized. `icon.png` is the window icon, and the executable embeds that same picture. The playfield is at least 800×600 and grows so the largest level fits, with 24 pixels of side margin and a 220-pixel lane under the lowest brick row. Each frame is drawn at that size and fitted uniformly into the window, with black bars when the aspect ratios differ. The mouse is mapped back through that fit. Target FPS is 500. Each level and each life sticks the ball to the paddle until left click. A still paddle sends it straight up at 1 pixel per frame. Paddle movement sets the launch angle and adds speed. That launch stays at 3 pixels per frame or under until `fast` is on. `fast` raises a slower ball's faster axis on each bounce, up to 267, and a ball already faster keeps its speed. A ball that leaves the screen leaves the others at that speed. `fast` ends when the last ball is gone.

## Session resume

When you work on this project, leave a script in the repo root that resumes your Grok session. Use `resume.ps1` on Windows, or `resume.sh` on Linux and Mac. It should `cd` to the repo root and run `grok --resume` with the id of the session you are in. That id is the directory name under `~/.grok/sessions/` for this repo.

Add that filename to `.gitignore` if it is not already listed. Do not commit the script.

At startup the game reads every `.txt` in `src/levels` and sorts that list by the number in the filename. That list is the level order. The game opens on a main menu over a black starfield. PLAY loads the first file. LEVEL SELECT lists one button per file over that same starfield, scrolling with the mouse wheel when the list overflows, and choosing one loads that file. TOTALS scales each saved run up from the center over that same starfield. BACK returns to the main menu. QUIT closes the window. An empty folder does not start play. When no brick has hit points left, the board freezes and a level-clear menu shows that level's score under `LEVEL SCORE`, wrapped to the playfield width. The round statistics follow it. Both rise together, like credits, and pass behind the title and the buttons. There is no solid black band. The last level also shows the total under that level score: `STATS`, the date and 12-hour time, `Total Score:`, `MAX SCORE nX +` when the run hit the cap, the digits with no commas, `LEVEL n` for the highest level reached, and `WON`. NEXT LEVEL loads the next file, clears falling drops, brick chips, and animations, resets the paddle width, the multiply timer, stick, fast, and the score, and sticks one ball to the paddle. Lives and super powerups carry into that next path. MAIN MENU returns to the main menu. The last level has no next path, so that menu only has MAIN MENU. When every ball is gone and no lives remain, the board freezes and `life_lost` plays once, huge, in the center, while the picture slams around by up to 48 window pixels. The paddle, balls, drops, chips, and the other animations stay frozen, and the multiply timer does not drain. The shake ends when that animation ends. When that animation ends, a you-lost menu shows that level's score under `SCORE`, then the same total with `LOST`, and the same scrolling statistics, then MAIN MENU and QUIT. Escape during play opens the pause menu. RESUME and Escape continue that board. MAIN MENU returns to the main menu. Starting from PLAY or LEVEL SELECT sets lives to 1. A new level and a spent life both stick the ball to the paddle until left click.

## Config

`rect_types.txt`:

```
symbol = name hitpoints COLOR {powerup chance%, ...}
```

`{}` means no drops. `parse_drop_tail` in `powerups.odin` reads that group. Chances are independent. `PAD` and `BALL` chances roll when the brick breaks. A `RECT` chance rolls when that brick is hit. The name loads `src/textures/<name>.png`. Colors are raylib names (`GREEN`, `ORANGE`, `RED`, and the other names in `color_from_name`) and are the fallback when that file is missing. A textureless 1 HP brick draws its symbol. A textureless dark brick draws a gray outline, and its label is white. Current types:

- `B` basic_rect, 1 HP, orange, no drops
- `W` rect_wide, 1 HP, green, `wide` 100%
- `O` rect_bomb, 1 HP, purple, `bomb` 100% and `bonus` 10%
- `I` rect_stick, 1 HP, brown, `stick` 100%
- `L` rect_life, 1 HP, blue, `life` 100%
- `M` rect_multiply, 1 HP, pink, `multiply` 100%
- `F` rect_fast, 1 HP, gray, `fast` 100%
- `T` tough_rect, 2 HP, yellow, `stick` 45% and `life` 20%
- `S` strong_rect, 3 HP, red, `wide` 50% and `multiply` 30%
- `U` super_rect, 10 HP, black, no drops
- `X` hyper_rect, 10000 HP, white, `bonus` 100%

`powerup_types.txt` is `name PAD`, `name BALL`, or `name RECT`. Comments under each name describe the effect. A new name needs both a line in that file and a case in code. The target decides delivery. The kind decides the effect. `PAD` falls and applies on a paddle catch. `BALL` applies as soon as the roll succeeds. `RECT` stays on the brick.

`super_powerup_types.txt` is one name per effect. Comments under that name say which MAX SCORE counts add a stack (`1x to 50x`, `4x to 12x`, or `5 thru 10`) and a percent when the effect is a chance. A line that adds a percent on each later MAX SCORE is the step. The game reads those ranges. A new name needs a case in code. Current names are `double`, `explode`, and `targeting`. Stacks add to each other. They stay until the last life is lost.

## What works

- The game opens on a main menu. The background is black. Ten copies of `src/textures/starfield_a.png` fly toward the camera. A sheet that passes the camera returns to the far start. Every 4 seconds one `starfield_b.png` does the same, a little faster, from farther away. Both fade in from black across the far part of that trip, and they are already mostly visible while they are still far. The PNG alpha is kept. Level select and totals use that same starfield, and the sheets keep moving between those screens. PLAY starts the first file in `src/levels`. That folder is `lvl1.txt` through `lvl100.txt`. Levels 21 through 100 are picture boards built as corridors of super rects and strong rects, and each one includes at least one hyper rect. LEVEL SELECT shows one button for each `.txt` file there, in number order, scrolling when the list is taller than the screen. Choosing a level starts there. BACK returns to the main menu. TOTALS draws each saved run in the center, oldest first, over that starfield. Each one reads the date and time as `mm/dd/yyyy h:mm:ss AM` when the line has a clock, or the date alone when it does not, then `Total Score:`, then `MAX SCORE nX +` when that run's cap count is above 0, then the digits with no commas, wrapped to 48 a line and drawn smaller than that heading, then `LEVEL n` for the highest level reached, then `WON` or `LOST`. An older line that is only a score omits those three. It starts tiny and grows at a steady zoom, fades in as it grows, and fades out quickly once it is bigger than the screen. The next one starts about 1 second after that zoom ends. The title and the buttons stay put. An empty list says `NO SCORES`. CLEAR SCORES wipes the list and `scores.txt`. QUIT closes the window. With no level files, PLAY does nothing.
- While `PLAY` or `LAST_LIFE` is up, the cursor is locked to the window with `rl.DisableCursor`. Menus (`MENU`, `LEVEL_SELECT`, `SCORES`, `PAUSE`, `LEVEL_END`, `LOST`) release it with `rl.EnableCursor`. The lock re-centers the mouse when it toggles, so the paddle follows from the middle after a resume.
- Right-click still clears the balls, but only while debug mode is on: type `6767` on the main menu. A yellow `DEBUG` label marks the whole game while it is active. The small `X` at the bottom right exits debug mode, and the paddle's right-click serve is disabled again. While debug mode is on, a column of debug buttons sits down the left edge: ADD LIFE, REMOVE LIFE, WIDE, MULTIPLY, STICK, LIFE, FAST, BONUS, BOMB, DOUBLE, EXPLODE, TARGETING, and CLEAR POWERUPS. They apply the same effect as that powerup. DOUBLE, EXPLODE, and TARGETING each add one stack of that super powerup, and a later one keeps the earlier stacks. TARGETING keeps adding until the chance is 100%. CLEAR POWERUPS resets the paddle width, stick, fast, multiply, and the speed bonus.
- Menus, the score, the stick, fast, and multiply labels, and textureless brick labels use `src/textures/font.png`. The sheet is 100×450, five columns and twenty-one rows of 19×20 cells. In order it is A–Z, a–z, three blanks, 0–9, `.` `"` `'` `,` `!`, `?` `-` `_` `/` `\`, `:`, `^`, a downward chevron, `>`, `<`, `+` `*` `#` `$` `%`, `@` `&` `(` `)` `[`, `]` `{` `}` `|` `;`, `~`, and a backtick, and the remaining cells are blank. The last row is empty. Black and the pink divider (255, 0, 110) are transparent, and the texture uses nearest-neighbor filtering. Space is the first blank after z. The letter v is the one drawn for v. One scaled divider pixel sits between characters. A missing file keeps raylib's default font.
- The playfield grows to the widest and tallest level and stays at least 800×600. The paddle top is 30 pixels above the bottom of that playfield. The frame is letterboxed into the window. Menus, the score, and the stick, fast, and multiply labels scale with the playfield. Bricks, the paddle, the ball, and the life icons stay at their original pixel sizes.
- Clearing a board freezes play and opens a level-clear menu. The heading is `LEVEL SCORE`. The digits wrap to the playfield width so the whole number can be read. Under a `STATS` heading, the crawl lists the time the level ran, powerups collected, balls lost, balls still in play, lives, lives lost, the paddle width, the max-score hit count, and one speed line for each living ball. That block scrolls upward and loops, passing behind the title and the buttons. The solid black band is gone. A dim overlay still covers the board. A one-shot animation already on screen keeps playing. NEXT LEVEL starts the next path at score 0 and keeps the remaining lives. MAIN MENU returns to the main menu. The `STATS` heading is larger than the other lines. The last level's menu has MAIN MENU only. Under `STATS` it shows the date and time as `mm/dd/yyyy h:mm:ss AM`, `Total Score:`, `MAX SCORE nX +` when the run's cap count is above 0, that total's digits with no commas, smaller than the heading, `LEVEL n`, and `WON`, then the same statistics.
- When every ball is gone and no lives remain, the board freezes and `life_lost` plays once at two thirds of the shorter playfield side, centered. The picture slams by up to 48 window pixels until that sheet ends. The paddle, balls, falling drops, brick chips, and the other animations stay frozen. The multiply timer does not drain. The space cube keeps turning. When that animation ends, a you-lost menu shows the wrapped score of the level still in play under `SCORE`, then the same total block with `LOST`, and the same scrolling statistics, then MAIN MENU and QUIT. The solid black band is gone there too. MAIN MENU returns to the main menu. QUIT closes the window. A cleared board still opens the level-clear menu when the last brick and the last ball go on the same frame.
- Escape during play opens the pause menu and freezes the board, the balls, the falling drops, the brick chips, the animations, the paddle, and the multiply timer. The space cube keeps turning. RESUME and Escape continue the same board. MAIN MENU returns to the main menu.
- The paddle follows the mouse. Its top is 30 pixels above the bottom of the playfield, its height is 20, and its width starts at 200. `src/textures/pad_center.png` is tiled across that width and grows with the paddle. `src/textures/pad_end.png` is drawn on the left end and, mirrored, on the right end, on top of the center. A missing center file keeps the white rectangle. The hit box is still that rectangle. While debug mode is on, right-click clears every ball, clears the fast speed bonus, and sticks one ball to the middle of the paddle. It does not spend a life, and `fast` stays on if it was already on.
- The ball leaves the top of the paddle in a new direction. Paddle movement is the average horizontal change over the last 16 play frames, and a jump bigger than 24 pixels in one frame counts as 24. A still paddle sends the ball straight up. A moving paddle aims the ball in that direction and raises its speed. The straight-up speed is 1 pixel per frame, or the current `fast` speed. Without `fast`, the faster axis of a paddle launch stays at 3 or under. With `fast`, it can reach 267. Side hits on the paddle push the ball out and reverse horizontal speed. Walls and bricks reflect the axis that was hit, so the angle continues. The hit shape is a circle of radius 12. `src/textures/ball.png` is drawn in that circle's 24×24 box with nearest-neighbor filtering while no super powerup is active. `ball_sp_0`, `ball_sp_1`, and `ball_sp_2` replace it for double, explode, and targeting, and the highest one that is on wins. Each of those sheets is four 16×16 frames with no grid, played from the bottom at 12 per second, and the frame holds while the board is frozen. A missing super sheet keeps `ball.png`. A missing `ball.png` draws a red circle. The paddle hitbox is the drawn rectangle. A ball already past the underside keeps falling. The ball does not bounce off the bottom of the screen. Once its center passes the bottom of the playfield it is removed. Movement is one pixel at a time, and a fraction of a pixel carries into a later frame. A new level, a spent life, and right-click place the ball stuck on the paddle. Left click launches it.
- Each level character with a known type becomes one brick. The grid is centered. Cells are 70×50 with a 5-pixel gap, first row at y=40. The cell is drawn with that type's texture, scaled from the 35×25 file with nearest-neighbor filtering.
- A hit spends 1 HP, or more while a double super powerup is active, and bounces off the face that was struck. The brick pictures jitter by up to 4 playfield pixels for a moment. The hit boxes stay put. A blast that damages a brick starts the same jitter. Pause holds whatever is left of it. The ball is placed one pixel outside that face, so a graze spends one hit point and does not keep spending them while the ball travels along the brick. The brick is gone at 0. Full health has no crack. Lost health picks an overlay: `crack_0` through a third gone, `crack_1` through two thirds, and `crack_2` after that. A 1 HP brick never shows a crack. A type with no texture file still draws its flat color. A 1 HP brick shows its symbol. One with more hit points dims as it loses them and shows the remaining points. A dark brick gets a gray outline and a white label.
- A ball hit throws chips of that brick. A hit that leaves it standing throws 8 from the face the ball struck. A hit that removes it throws 24 from across the cell. Each chip is a patch of that brick's texture. A brick with no texture throws squares of its color. Chips drift outward, fall, and fade. At most 256 are alive, and a new burst drops the oldest. Pause, the last-life animation, the level-clear menu, and the you-lost menu freeze them. Starting a level clears them. A bomb blast does not throw chips.
- A ball that leaves the board plays `ball_lost.wav`, along its animation. A non-final life plays `life_lost.wav`; the last life plays `last_life_lost.wav`. A wall or paddle bounce plays `ball_bounce_wall_pad.wav`. A paddle catch of a `PAD` drop plays `pad_collect_powerup.wav`. A click on a menu button plays `menu_button_click.wav` at 0.75. The level score hitting the cap plays `max_score.wav`, along the flash.
- `src/sounds/Rect_Destroyer.wav` is the theme. It starts with the window and loops. The main menu, level select, and totals play it at 1.25. Play, pause, the level-clear menu, the last life, and the you-lost menu play it at 1. The same stream keeps going when a level starts. A missing file leaves the music silent. Pause does not stop it.
- A ball hit that leaves the brick standing plays `src/sounds/hit_0.wav`. A ball hit that removes it plays `src/sounds/destroy_0.wav`. Strong and super play `hit_1.wav` and `destroy_1.wav` instead. Tough uses the `_0` clips with the other bricks. The variant comes from the first word of the type name. A blast that damages a brick does not play either clip. A bomb brick that explodes plays `bomb_explode.wav`, including one started by a chain. A ball that destroys a bomb brick plays `destroy_0` as well. Each clip is loaded once and has a second voice that shares those samples, so two plays of the same clip can overlap. A third play restarts one of them. A missing file is skipped. Pause leaves a sound that has already started to finish.
- Destroying a brick adds `1 * (12000000000000 / elapsed_ns - elapsed_ns / 60000000000)`. `elapsed_ns` is nanoseconds since this level started, and at least 1. Pause time is not counted. The multiplier is not clamped. A 10-nanosecond break is 1.2 trillion. The multiplier is 0 at 14 minutes and -24 at 30 minutes, so that brick is worth -24. That running total is what `SCORE` shows during play and pause. After a ball bounces off the paddle or a brick, the next brick that same ball hits doubles the score, before that brick's points are added. A hit that leaves the brick standing counts the same as one that destroys it. A wall does not. Sticking to the paddle does not end the trip. If that ball leaves the bottom before the next brick, the score is halved and rounded to the nearest integer, and a half rounds away from zero. A launch that has not bounced yet does neither. Each ball keeps its own trip. Right-click does not halve the score. When the board clears or the last life is lost, the round is scored once, in this order. Each collected powerup adds 2. A collected powerup is a `PAD` drop the paddle caught, or a `BALL` drop that applied when its brick broke. `bomb` stays on the brick, so it is not collected. Each extra paddle length of 50 pixels multiplies the score by 10. A pad that grew by less than one full step does not. Each ball still in play adds 10. Each ball whose center passed the bottom of the playfield subtracts 15. Right-click does not count as a ball lost. Each life still held adds 100. Each life lost this round subtracts 500. If no life was lost and at least one remains, the score is then multiplied by the lives times 150. Each ball still in play adds 10 for each whole pixel per frame of its faster axis. A stuck ball with no speed adds none of that. Once the cap has been reached in the level, the level score reads `MAX SCORE nX +` and its comma-separated digits. The total's digits are not comma-separated. The score is a big integer, but it still has a ceiling. While a level runs, hitting the 2048-bit signed maximum (±(2^2047 - 1)) counts once on MAX SCORE, resets that level's total to 0, and flashes `MAX SCORE` in big yellow text; later hits burn through `MAX SCORE nX`. Each of those caps adds one super powerup, and that stack stays for later levels until the last life is lost. Run sums and the total saturate at the cap instead. The same counts are added into the stats crawl. The same settled total is the one-line `SCORE` during the last-life animation. On the level-clear menu the heading is `LEVEL SCORE`. On the you-lost menu the heading stays `SCORE`, because that number is the level still in play and the statistics describe it. Both wrap the digits, and they scroll with the statistics when the list is taller than the menu. The clock in that list is the time when the round was scored. The score resets when a level starts. Each finished level is added into the run once, including the level where the last life is lost, so that loss keeps the level's score instead of forcing the total to 0. The total score is that sum times the number of levels finished. PLAY and LEVEL SELECT start a new run at 0. NEXT LEVEL keeps the sum and the count. Each finished level also adds its own cap hits into the run's max-score count, and the highest level number reached is kept. The total is drawn under the level score when the last level is cleared, and under the failed level's score when the you-lost menu opens. It reads `STATS`, the date and time as `mm/dd/yyyy h:mm:ss AM`, `Total Score:`, `MAX SCORE nX +` when the run's cap count is above 0, then the digits with no commas, then `LEVEL n` and `WON` or `LOST`. That total is appended to `scores.txt` in the working directory, newest last. A line is `<stamp>=<score>;<max score count>;<level>;<W or L>`. Older lines that are a stamp and a score, or only a score, still load and omit the extra lines. A line whose score is not an optional minus and digits is skipped. A missing file is an empty list. TOTALS reads that file. CLEAR SCORES empties the list and the file. Returning to the main menu before the last life or the last level does not write a line.
- `PAD` powerups fall from the broken brick at 90 pixels per second. They apply only if the drawn paddle overlaps them. A miss leaves the screen and does nothing. Each drop draws `src/textures/powerup_<name>.png` at 50×50, the 16×16 file scaled with nearest-neighbor filtering. That rectangle is the catch box. A missing file draws the old colored letter: `wide` gold with `W`, `stick` brown with `S`, `life` blue with `L`, `multiply` yellow with `M`, `bomb` purple with `B`, and `fast` orange with `F`.
- `wide` adds 50 pixels per catch, up to 40 pixels short of the screen width. That 50-pixel step is the "widen by 1" note in `powerup_types.txt`.
- `BALL` powerups apply as soon as the roll succeeds. `multiply` lasts 10 seconds. While it is active, a hit on a brick that still has more than 1 HP doubles the living balls from that spot, up to 32. New balls reverse horizontal speed. The timer is the `x2` label at the top left. Extra balls stay after the timer ends. Pause does not drain that timer.
- `bomb` runs when its brick is hit and the chance roll succeeds. The brick's orthogonal neighbors each lose 1 HP. A bomb neighbor can explode from that hit, once per chain. Diagonal bricks are not hit. Bricks destroyed by the blast score and roll their own drops. The ball's own hit is what scores the bomb brick.
- `stick` arms one landing. A ball moving downward that lands on the top half of the paddle sticks to that spot and follows the paddle, and the arm turns off. The `STICK` label goes away then, including while that ball is still stuck. Left click launches it one pixel clear of the paddle. A still paddle sends it straight up at the current fast speed. A moving paddle aims that launch and speeds it up. If two balls land on the same frame, the first sticks and the other bounces. A side hit still bounces. Another `stick` catch arms one more landing. A new level and a spent life also place the ball on the paddle, with `stick` still off, so the label stays off and the next landing bounces.
- `life` adds one life per catch. The count starts at 1. That 1 is the life in play. `src/textures/life_point.png` is drawn once for each life at 80×80 along the top left, under the multiply timer and clear of the score. Extra icons continue to the right, then wrap downward. They are drawn before the paddle, the bricks, the balls, the chips, and the drops, so those cover them. A half-alpha copy of the same icons is drawn after the bricks and before the balls, chips, and drops. `life_lost` plays in that same 80×80 box, with the other animations, so it stays in front. The last life plays that sheet once at two thirds of the shorter playfield side, centered, on top of the board, and the you-lost menu waits until it finishes. A missing file draws a blue square of the same size. `STICK` and `FAST` sit under the icon row. When every ball is gone, one life is removed. If any remain, a new ball sticks to the paddle on the same board, and the picture jitters for about a third of a second. The offset is a few window pixels and fades out. Pause holds whatever is left of that jitter. The last life shakes much harder, up to 48 window pixels, for the whole centered animation, and the you-lost menu arrives after the shake stops. Paddle width, stick, multiply, and the bricks stay. `fast` and its speed bonus end with that last ball. Reaching 0 does not serve another ball. NEXT LEVEL keeps the remaining lives. PLAY and LEVEL SELECT start the count at 1.
- `fast` lasts while any ball is still in play. Each bounce adds 1 to a shared speed bonus. That bonus is a floor: a living ball slower than `1 + bonus` is raised to it, up to 267 pixels per frame, and keeps its angle. A ball already faster, including one a moving paddle just launched, keeps that speed when any ball bounces. A ball that leaves the screen leaves the others at their current speed, with `fast` and the bonus still on. `fast` turns off and the bonus returns to 0 when the last ball is gone. Catching `fast` again is what turns it back on. A paddle launch without `fast` keeps its faster axis at 3 or under. The `FAST` label shows `1 + bonus` while it is on.
- Each time the level score hits the cap, one super powerup is added. The stack is kept when NEXT LEVEL starts. It clears when the last life is lost, and when PLAY or LEVEL SELECT starts a new run. `double` is MAX SCORE 1x through 50x. Each stack doubles the damage of a ball hit, so 1x deals 2 and 2x deals 4. The hit point is a 32-bit count, so the damage stops doubling at 1,073,741,824 and later stacks in that range stay there. `explode` is 4x through 12x. A ball hit also blasts every other brick within that many grid steps for 1 HP. The first stack is the four orthogonal neighbors. Each later stack reaches one step farther, out to nine steps at 12x. `targeting` starts at 5x. From 5x through 10x, each bounce rolls a 10% chance. Each MAX SCORE after 10x adds 5%, up to 100%. A success sets that ball's velocity along the straight line to the center of the nearest other living brick and keeps its speed. That angle stays until the next bounce, so the ball flies at the brick instead of curving around it. If that line would step back into the pad, a wall, the ceiling, or the brick just hit, that part of the speed stays off the surface and the rest still points toward the brick. A miss leaves the bounce direction alone. Sticking is not a bounce. The three effects stay on together. `DOUBLE` shows the hit damage, `EXPLODE` shows the step radius, and `TARGETING` shows the chance. Those labels sit with `STICK` and `FAST`. The ball's own hit still scores, shakes, and throws chips once. The blast shakes each brick it hurts, scores a brick it destroys, and can set off a bomb it damages. It plays `explode` on the struck cell, sized to that blast, and `bomb_explode.wav`.
- `src/textures/space_bg.png` covers the inside of a cube drawn behind the playfield, pause, the level-clear menu, and the you-lost menu. A level numbered above 19 also puts `src/textures/galaxy_bg.png` on the inside of one face. The other faces stay `space_bg.png`. Once the run reaches MAX SCORE, five copies of `src/textures/max_score_effect_field.png` fly toward the camera on top of the cube. They stay through later levels, and they clear when the last life is lost or a new run starts, the same as the super powerups. They loop the way the menu starfield does, and they move faster than it. They fade in from black a little farther from the camera than the menu sheets, and they are already fully visible while they are still farther out. They do not replace the cube. The main menu, level select, and totals draw the starfield instead. The camera stays at the center of that cube. The cube turns on X, Y, and Z together, from the time since the window opened, so pause, the level-clear menu, and the you-lost menu do not stop it. The max-score sheets keep moving then too. The letterbox bars stay black. A missing file leaves the black background.
- `src/textures/animations` holds `ball_lost`, `ball_trail`, `explode`, `life_lost`, `hyper_rect`, and `ball_sp_0` through `ball_sp_2`. Each sheet except `ball_sp` is split by a magenta grid (255, 0, 255). That grid is not drawn. Frames play from the bottom of the sheet to the top, 12 per second, with nearest-neighbor filtering. `ball_lost` plays once at the bottom of the playfield, centered on a ball whose center passes that edge, at 3× the frame size. `life_lost` plays once in the 80×80 slot of a life icon that just disappeared. The last life plays it huge in the center instead, the picture slams by up to 48 window pixels, and the rest of the board stays frozen until the sheet ends. `explode` plays once as a square centered on the brick. A bomb is a little larger than the 70×50 cell. A super explode grows with that blast's radius so the square covers the bricks the blast reaches, and the size stays fixed for that play. That sheet is drawn behind the bricks, and a half-alpha copy is drawn in front of the bricks, the same way the life icons are. A bomb stays a single full-alpha sheet in front of the board. A bomb set off by the blast stays at the smaller size. `ball_trail` loops with the sheet's right edge on a ball whose faster axis is above 1.5. The frame is stretched to three times its width and points opposite the ball's movement, over the bricks. A stuck ball does not show it. Just above 1.5 the trail is faint, and it is fully opaque at 267. Pause freezes every animation. The level-clear menu and the you-lost menu keep a one-shot playing and hold the trail on its current frame. Starting a level clears them.

- `bonus` is a `BALL` powerup. When its brick breaks and the roll succeeds, the level score is squared. It counts as a collected powerup.
- A brick type whose name matches a sheet in `src/textures/animations` (a matching `.animation` file) draws its picture by looping that sheet's frames instead of a flat PNG. `hyper_rect` is that kind. Frames normally split on the ring of pink grid rows; a sheet without a grid declares its cell size in the `.animation` text as `WxH` (`hyper_rect` uses `35x25`). The animation freezes with pause, the last-life shake, and the end menus.

## Quirks worth leaving alone unless asked

- During play, a mouse-position string is formatted every frame and not drawn.
- Same-package files see each other's types. Do not add an import between them.
- When adding levels, create only new files. Do not overwrite a `.txt` file that is already in `src/levels`.
